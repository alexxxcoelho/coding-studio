# Analyser : des codes aux thèmes {#analyser}

## Pourquoi cette étape {#analyser-pourquoi}

C'est ici que l'analyse thématique se fait. Braun et Clarke (2006, 2021) insistent : les thèmes ne « émergent » pas des données, ils sont construits par le chercheur à partir des codes, en fonction de ses questions. Un thème n'est donc pas un sujet (« les coûts ») mais une proposition analytique (« l'adoption dépend de l'alignement entre l'effort demandé et la valeur reçue »), qui peut être nuancée ou contredite, et c'est ce qui la rend vérifiable. La seconde moitié de l'étape applique la méthode du cadre de Gale et al. (2013) : une matrice dont les lignes sont des cas et les colonnes des thèmes ou des codes, pour comparer les entretiens sans perdre le lien avec les passages. L'étape est itérative : un thème renvoie à ses codes, un passage à son entretien.

## Ce que vous faites {#analyser-actions}

### 1. Regrouper les codes {#analyser-regrouper}

Avant de formuler des thèmes, vérifiez que vos codes sont regroupés. Un code focalisé est un parent qui réunit des codes descriptifs voisins, par exemple « Absence de besoin » sur « Prêt papier jugé suffisant » et « Peu d'emprunts par jour ».

**Dans Coding Studio.** Dans le Codebook, glissez les codes descriptifs sous un parent (voir [Coder](02_coder.md#coder-codebook)). Pour chaque groupe, ouvrez les passages du parent et vérifiez que vous pouvez dire en une phrase ce qui les relie. L'outil ne calcule aucun regroupement à votre place.

### 2. Créer un thème {#analyser-themes}

Un thème regroupe des codes et porte une interprétation. Il est construit après le codage.

**Dans Coding Studio.** Cliquez sur Analyser dans la barre du haut. La colonne Thèmes liste vos thèmes, avec un bouton Nouveau thème. Pour chaque thème, la liste montre le titre, le statut, les codes supports et le nombre d'entretiens concernés. Cliquez sur Nouveau thème, puis saisissez un titre qui affirme quelque chose. Exemple fictif : « La non-adoption n'est pas toujours un échec : certaines petites bibliothèques n'identifient aucun besoin que le nouveau système de prêt réponde. » Glissez ensuite des codes dans le thème. Un code peut servir deux thèmes. Le titre d'un thème est modifiable ; l'ancien reste dans l'historique.

### 3. Remplir la fiche de thème {#analyser-fiche}

La fiche est le dossier de défense du thème.

**Dans Coding Studio.** Cliquez sur un thème pour ouvrir sa fiche. Elle contient : la proposition en deux à quatre phrases ; les questions de recherche concernées (Q1, Q2, ...) ; les codes supports ; les cas qui étayent ; les cas divergents ; les conditions (par exemple, un petit volume de prêts) ; l'interprétation alternative ; les limites ; le statut ; le mémo de décision. Les cas et les passages se rattachent depuis la matrice (action 6) ou depuis l'exploration. Remplissez d'abord la proposition et les cas divergents : un thème sans cas divergent examiné est suspect.

### 4. Régler le statut et passer les contrôles {#analyser-statut}

Un thème passe par trois statuts : candidat, révisé, retenu. Retenu signifie que vous êtes prêt à le défendre.

**Dans Coding Studio.** Dans la fiche, le sélecteur Statut propose Candidat, Révisé, Retenu. Le bouton Contrôles avant « retenu » (liste de l'étude, 7 par défaut) ouvre une liste à cocher. Par défaut :

1. Les extraits sont-ils cohérents entre eux ?
2. Le thème se distingue-t-il des autres ?
3. L'intitulé affirme-t-il quelque chose plutôt que de nommer un domaine ?
4. Le thème est-il central pour au moins une question de recherche ?
5. Repose-t-il sur plusieurs observations, ou sur un cas unique justifié comme révélateur ?
6. Quelles données le nuancent ou le contredisent, et sont-elles traitées ?
7. Les citations retenues suffisent-elles à soutenir exactement l'étendue de l'affirmation ?

La liste se modifie dans les Réglages : vous pouvez en ajouter, en retirer ou les reformuler. Le mémo de décision, en bas de la fiche, explique en quelques lignes pourquoi le thème est conservé. Les contrôles sont une aide à la décision, pas un verrou : l'outil ne passe jamais un thème à « retenu » à votre place.

### 5. Lire les thèmes avec un cadre, si vous en avez choisi un {#analyser-cadre}

Le cadre d'interprétation est facultatif. S'il est choisi dans les Réglages, il apparaît ici et dans Rédiger, nulle part ailleurs.

**Dans Coding Studio.** Dans la fiche d'un thème, le sélecteur Lecture par le cadre affiche les dimensions du cadre choisi (pour TOE : T, O, E) et une case « hors cadre ». Cochez ce que le thème explique et, dans le mémo, ce qui lui échappe. Un thème peut tenir en partie hors du cadre : c'est une information, pas un défaut. Sans cadre, ce sélecteur n'apparaît pas. Le cadre apparaît seulement ici et dans Rédiger.

### 6. Régler la matrice {#analyser-matrice}

La matrice compare les entretiens sur plusieurs thèmes ou codes. Elle se règle selon la question que vous vous posez.

**Dans Coding Studio.** Sous les thèmes, l'onglet Matrice offre deux sélecteurs. Lignes : les entretiens, les cas ou un attribut d'entretien (par exemple le type de bibliothèque). Colonnes : des thèmes, des codes focalisés, ou des dimensions personnalisées que vous avez définies dans les Réglages (par exemple « qui impose le système », « qui finance », « décision et situation »). Chaque combinaison est un réglage de la même vue : une matrice cas par thème, une matrice type de bibliothèque par coût supporté, une matrice question de recherche par extraits sont trois réglages, pas trois outils.

### 7. Lire une cellule {#analyser-cellules}

Chaque cellule résume ce que dit un entretien sur une colonne, sans cacher sa source.

**Dans Coding Studio.** Cliquez sur une cellule : le panneau Cellule (entretien, colonne) s'ouvre sous la matrice, avec les passages concernés, leurs citations et les mémos liés. Vous y choisissez la valeur dans un menu (présent, non évoqué, contredit ou incertain) et pouvez ajouter un résumé d'une ligne (« le lot suffit »). Le nombre de passages est calculé par l'outil. Un entretien non encore codé affiche « pas encore codé ». Non évoqué ne veut pas dire absent dans la réalité : le sujet n'est pas venu dans l'entretien. Les compteurs distinguent toujours passages et entretiens : sept passages dans deux entretiens ne font pas sept répondants.

### 8. Filtrer pour faire apparaître les contrastes {#analyser-filtres}

Les contrastes entre groupes sont souvent plus instructifs que les moyennes.

**Dans Coding Studio.** Au-dessus de la matrice, la barre de filtres propose les attributs saisis dans la fiche des entretiens (voir [Préparer](01_preparer.md#preparer-attributs)). Par exemple, filtrez sur le statut des propos « déploiement vécu » pour comparer ceux qui ont vécu le changement, ou sur le type « scolaire » pour ne voir que ce groupe. La matrice se recalcule. Les filtres ne modifient aucun codage.

### 9. Explorer les données {#analyser-explorer}

L'exploration sert à tester une intuition ou à retrouver ce que vous avez manqué.

**Dans Coding Studio.** L'onglet Explorer offre quatre outils : la recherche d'un mot en contexte (KWIC) sur tous les entretiens, avec les mots voisins de chaque occurrence ; les passages par code, tous entretiens confondus ; les passages proches par vocabulaire (voir [Coder](02_coder.md#coder-lexique)) ; et le tableau codes par attribut, qui ventile le nombre de passages de chaque code selon une valeur d'attribut. Ces outils explorent, ils ne concluent pas. Un clic sur un résultat ouvre le passage dans son entretien.

### 10. Documenter les décisions {#analyser-decisions}

Certaines études observent des décisions concrètes. L'onglet qui les rassemble sert d'illustration.

**Dans Coding Studio.** L'onglet Décisions documentées liste les décisions créées. Cliquez sur Nouvelle décision : donnez un nom (par exemple « Bibliothèque de la commune X, nouveau système de prêt »), l'issue (adopter, différer ou refuser) et les caractéristiques utiles à votre étude, puis rattachez-y des unités de n'importe quel entretien. Une décision sans unité rattachée est marquée non documentée. Cet onglet complète l'analyse par thèmes sans la remplacer.

### 11. Exporter le rapport analytique Word {#analyser-rapport}

Le rapport réunit les résultats déjà rédigés et leur dossier de preuves. Il prépare la rédaction d'un chapitre de résultats ; il ne rédige pas de nouvelles interprétations à votre place.

**Dans Coding Studio.** Dans Analyser, cliquez sur Rapport analytique Word. Actualisez d'abord les fiches de thème, les cinq parties de Rédiger, les réponses aux questions et les cellules de matrice commentées. L'export rassemble le corpus et son périmètre, les thèmes retenus avec leurs passages, les réponses aux questions, les comparaisons entre entretiens, les preuves liées manuellement à la matrice, le cadre choisi, les décisions documentées, le codebook et la traçabilité. Les thèmes non retenus et les preuves hors résultats restent identifiés séparément. Le dossier est daté et comporte un manifeste.

La génération du fichier Word n'appelle aucun modèle : elle met en forme le contenu enregistré. Cela n'efface pas une assistance IA utilisée auparavant pour construire ou revoir ce contenu. Conservez cette provenance dans la méthode ; n'annoncez pas une analyse sans IA si elle en a utilisé. Avant toute reprise dans la thèse, relisez les affirmations contre leurs sources, contrôlez les citations à l'audio et conservez les limites et cas divergents. Un document complet n'est pas une certification de validation scientifique.

## Pièges fréquents {#analyser-pieges}

- Nommer un thème par un sujet (« Coûts »). Si le titre n'est pas une phrase qui peut être contredite, ce n'est pas un thème.
- Prendre la fréquence pour de l'importance. Un mécanisme rare peut éclairer une condition ; un mot répété peut ne rien expliquer.
- Lire le silence comme une absence. Non évoqué dit seulement que le sujet n'est pas venu.
- Retenir un thème sans cas divergent examiné, ou sans interprétation alternative.
- Plaquer le cadre : si tout rentre sans reste dans le cadre, relisez, c'est peut-être qu'il fait écran. Une part « hors cadre » est normale.

## Ce qui sort de cette étape {#analyser-sortie}

- Un jeu limité de thèmes, chacun avec une proposition, des cas qui l'étayent, des cas divergents, des limites et un statut.
- Des mémos de décision qui disent pourquoi chaque thème est conservé ou abandonné.
- Une ou plusieurs matrices annotées, filtrables par attribut.
- Éventuellement, une lecture par le cadre choisi et une liste de décisions documentées.
- De quoi passer à la rédaction : chaque thème retenu renvoie à ses passages.

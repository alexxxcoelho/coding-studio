## Choices to keep in mind

- **Identity layer on top of the legacy token.** `codes.code` (upper-case token) stays the key of the unit-level `human_codings`, the AI pass, the prompt and the older routes. `code_id`, `name`, aliases and `parent_id` sit next to it. A rename changes the name only. This keeps `e2e.rs`, the exports and the AI pipeline intact.
- **"Plus tard" is virtual.** It is the code `LATER` served by the code list, not a row of `codes`; it never reaches the prompt, the codebook export or any count. Passages parked with it are listed per interview (`/api/interviews/{id}/later`).
- **Offsets** are Unicode scalar positions, end exclusive; `start_utf16` and `end_utf16` are returned for browser selections and `offset_unit: "utf16"` is accepted. Staleness is computed at read time from the digest of the unit text with corrections applied.
- **Codebook version** is the number of rows of the append-only `codebook_revisions` table. Every change of the codebook (import, create, edit, activate, merge, rename, move, alias, create from passage) adds one row, so it is audited twice: the revision and the audit event.
- **A whole-unit passage does not write the unit-level `human_codings`.** The two representations coexist in V1 lots 1 and 2; the synchronisation is for lot 4 (coding screen). Until then, phase 2 blind coding and the agreement tables only read `human_codings`.
- **Project configuration is a separate settings key** (`project_config`), not a field of `StudyConfig`: `StudyConfig` feeds the prompt and its type is already used by the guard on phase 1 categories. The interpretive framework therefore cannot reach the prompt.
- **Memo template versions** are assigned by the server and the previous version is kept in `memo_history`, so an interview keeps the questions it was answered with and shows `outdated` when the template moved on. Choosing the same template again moves it to the current version.
- **Per-interview data** (attribute values, memo, checklist) is one JSON document per kind in the table `interview_data`, written inside a transaction with its audit event.
- **Template import** replaces lists and adds or updates what the file lists, keeps what carries data (an attribute with values, a memo template in use, research questions it does not list), reports every problem, and writes nothing on `dry_run` or on a problem. The research questions SQ1 to SQ3 that a codebook import creates with an empty text stay beside the template's Q1 to Q3.
- **Checklist default.** The fourth item is "Questions pour les suivants notées" (task brief). The guide (`docs/guide/fr/02_coder.md`) lists "mémo de fin d'entretien rédigé" instead; the owner should align one of them.
- **Fixed on the way.** The CSV and JSON codebook imports did not assign ids; they do now (and add a revision). `codebook.csv` gained six trailing columns; the import reads columns by name and is unaffected.
- French default labels contain no long dash and no emoji (checked by a test).
